# Vibe Gallery 当前功能与实验流程

更新日期：2026-07-27

## 平台定位

Vibe Gallery 是一个异步的 social vibe-coding 协作平台。它不把评论停留在“讨论”，而是让社区成员把多条评论组织为可追溯的综合方向，再由 App 的 Creator 在平台内将 Host 锁定的方向开发为可运行的 Community Version。

首页是瀑布流画廊。每位 Creator 自由发布自己的 Initial App；任意已发布 App 立刻可以被所有参与者浏览、评论和回复，不等待 6 个作品或 Host 开始研究。

## 参与者与条件

- `H01`：Host，负责开始/结束研究，并推进两个开发阶段。
- `C01–C12`：Creator，每人发布一个自由主题的 Initial App；Host 在研究开始前手动选择 6 人进入 Control，其余 6 人进入 Vibe Gallery。
- `P01–P24`：Community Commenter；Host 在研究开始前手动选择 12 人进入 Control，其余 12 人进入 Vibe Gallery。所有人都能看到并评论全部已发布 App，没有作品可见性限制。
- Control：普通社交评论与回复；Creator 在外部 vibe-coding 工具中开发后上传 HTML。
- Vibe Gallery：在普通社交互动基础上，增加收藏夹、两轮综合、来源连线和平台内 AI 原型开发。

新研究建立后，系统不再随机分组。Host 必须在控制台明确选择并保存对照组成员，人数满足 `6 Creator + 12 Community Member` 后才能记录正式研究开始；研究开始后分组锁定。

## Vibe Gallery 的用户流程

### 1. Initial App 与异步讨论

Creator 发布 Initial App 后，任何参与者都可在详情页：

- 发表普通评论；
- 回复任意评论；回复以统一尺寸的小卡片挂在原评论下方，不再随嵌套深度继续缩小；
- 随时给别人的普通评论或综合评论点赞，也可以取消赞；
- 将一条普通评论、回复或已有综合收藏到自己的收藏夹。

收藏夹是私有的跨 App 素材库。收藏本身不会让其他 App 的评论长期出现在当前画布：只有进入综合选材时，收藏内容才会临时显示；发布综合后，实际被采用的跨 App 内容才会作为正式来源节点保留。

### 2. 第一次综合：评论 → 可开发方向

研究开始后，画布开放“创建第一次综合”。参与者点击按钮进入选材模式：

1. 点击左侧的普通评论、回复或来自收藏夹的评论；卡片出现爱心效果并进入本次综合篮，点击篮中卡片可放回；
2. 可以只选择一条，也可以选择任意多条来源，不设上限；
3. 确认来源后，提示词输入框默认填入全部所选评论文本；
4. 用户需要理解并融合这些 idea，重新写成一段可直接用于 vibe-coding 的完整提示词；
5. 该提示词会完整显示在综合评论卡片上，供其他参与者点赞；
6. 每个人在同一 App、同一轮只能发布一条综合评论，但普通评论和回复不限次数。

来源卡片与综合评论之间自动连线。被采用的评论组会排在靠上位置；评论回复仍紧贴原评论，而不是混入独立的平铺列表。评论内容超过卡片默认展示长度时，可在卡片内展开或收起。

### 3. Host 锁定第一次开发

Host 在每个实验组 App 都至少有一条可评选评论后，点击“锁定最高赞评论并进入第一次开发”。普通评论、回复和综合评论共用同一种点赞规则，参与者可以给任何评论（包括自己的评论）点赞，也可以随时取消赞。锁定时，系统对每个 App 将普通评论与综合评论放在一起比较，选择赞数最高者进入开发；平票时优先选择发布时间更早的评论，再以类型和 ID 保证结果稳定。Host 的作用是决定何时截止并启动开发，而不是逐条主观挑选。

被锁定方向的直接与递归来源贡献者会立即收到站内消息；下次登录时可在消息栏看到，首次打开未庆祝消息会出现烟花效果。

Host 在本轮尚未开始生成、上传 Community 草稿或发布 Community Version 时，可以点击“返回上一阶段”。系统会撤销本轮锁定、恢复各 App 上一轮的入选方向，并移除本轮尚未生效的贡献通知；开发一旦开始，按钮即禁用，以免破坏版本与实验数据。

### 4. Community Version 1：平台内原型开发

只有目标 App 的 Creator 能开发该 App，且只能开发 Host 锁定的候选：

- V1 固定基于 Initial Version；
- 若综合评论入选，系统将综合提示词、完整来源链和基础版本交给平台内 AI；若普通评论入选，则直接使用该评论文本；
- Host 锁定后，系统自动把最高赞评论的文本带入开发，不要求 Creator 重新复制或重写；
- Creator 可试玩草稿、继续让 AI 修改，并确认发布 Community V1；
- 首页保留 Initial Version 原始卡片；App 发布社区版本后，在其右侧生成一张等高等宽的最新 Community Version 卡片。两张卡片相邻展示，明确它们属于同一个 App，同时社区卡片始终只呈现最新已发布版本及其真实来源。

对照组在同一开发阶段用外部工具完成 V1 后上传；平台不提供综合画布和平台内 AI 开发入口。

### 5. 第二次综合与 Community Version 2

某个 App 的 V1 发布后，画布增加第三、四列：

- 第三列显示针对 Community V1 产生的第二轮评论、回复，以及第二轮采用的跨 App 来源；
- 第四列显示第二次综合评论；
- 创建第二次综合时，可以选择第一列、第二列或第三列中的评论、回复、第一次综合及合规的收藏夹来源；
- 可以只选择一条，也可以选择任意多条来源；
- 确认后系统把来源正文预填为提示词，用户重新理解、融合和改写后形成第二次综合评论；
- 每个人在目标 App 的第二轮仍只能提交一次综合评论；普通评论和综合评论都可以继续点赞或取消赞。

当全部实验组 App 都已发布 V1，且每个 App 至少有一条第二轮可评选评论时，Host 点击“锁定最高赞评论并进入第二次开发”。系统只在针对 Community V1 新产生的第二轮普通评论、回复与第二轮综合评论中统一选择当前赞数最高者；第一轮普通评论和第一轮综合评论不再进入第二次开发评选。V2 **固定基于 Community V1**继续开发。每个 App 最多发布 V1 和 V2 两个 Community Version，所有旧评论、综合和版本仍会保留用于追溯。

## 画布结构

```text
第一轮评论与采用来源 ──→ 第一次综合 ──→ Community V1
          │                   │
          └─────────┬─────────┘
                    ↓
          第二轮评论与采用来源 ──→ 第二次综合 ──→ Community V2
```

- 第一列：Initial Version 下产生的第一轮评论、回复与第一轮采用来源；
- 第二列：第一次综合评论；
- 第三列：Community V1 下产生的第二轮评论、回复与第二轮采用来源；
- 第四列：第二次综合评论；
- 连线只表示直接来源；点击“来源”可查看作者、原 App、版本和正文；
- 卡片不能自由拖动，位置由系统稳定排列，方便阅读来源关系而不变成无限画板。

## 数据记录与研究可分析性

系统记录 App 与版本、普通评论树、收藏夹、每轮综合、直接来源、普通评论与综合评论的点赞/取消点赞、Host 锁定时的统一最高赞结果、开发任务、AI 交互、发布、贡献通知和关键行为事件。

这支持分析：

- 评论如何成为综合方向，再进入 V1/V2；
- 每个 Community Version 吸收了多少不同贡献者、评论、回复和跨 App 来源；
- 哪些来源被多个参与者反复选择；
- Control 与 Vibe Gallery 在评论到可运行原型的路径、操作负担和来源可追溯性上的差异。

自动验证脚本：`npm run test:community-gallery`。它覆盖即时评论、回复关系、跨 App 收藏、单来源与多来源综合、每人每 App 每轮一次提交、普通评论和综合评论点赞/取消点赞、跨类型最高赞锁定、普通评论直接进入开发、Host 两次锁定与安全回退、V1/V2 门控、固定 V2 版本谱系和通知。
