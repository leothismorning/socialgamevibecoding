# Vibe Gallery 当前功能与实验流程

更新日期：2026-08-07

## 参与者与登录

- Host：账号 `0`，密码 `0`。
- Creator：账号为实验编号 `1–50`，密码与实验编号相同。
- 数据库内部使用 `H01`、`C01–C50` 作为稳定研究编号；原有 `C01–C30` 保持不变，只新增 `C31–C50`。

## 单次实验与测试角色

平台只运行一种实验流程，不再提供对照组或对照功能。Host 在研究开始前选择若干 Creator 作为测试角色并保存。保存后：

- 测试角色只能看到测试角色创建的作品和相关互动；
- 正式角色只能看到正式角色创建的作品和相关互动；
- Host 可以查看和管理两类数据；
- 作品、版本、评论、综合评论、点赞、收藏、分配、通知和开发任务都遵守同一隔离边界；
- 测试流程与正式流程分别保存总流程的开始状态和结束时间；
- 每个 App 独立保存当前轮次，一边或一个 Creator 的推进不会改变其他人的阶段；
- Host 面板提供两个总流程开关，以及按 Creator 单选或多选的独立开发锁定区；
- 任一流程开始后测试角色名单锁定，避免中途切换导致实验数据混杂。

## 创作与社区开发

Creator 可以让 AI 生成初始草稿，也可以点击旁边的“从本地恢复项目”，把之前保存的项目代码恢复为当前草稿。系统会优先使用 Creator 已填写的应用名称，否则从 HTML 的 `<title>`、`<h1>` 或文件名推断名称；恢复后仍需预览确认并点击“发布并且保存”，才会作为新的 V0 出现在平台。

Creator 发布 Initial App 后，在 Host 开始研究后可以体验同一角色空间内的其他作品，并进行普通评论、回复、点赞、收藏和综合评论。作品点赞按版本分别记录：首页 V0 卡片、最新社区版本卡片以及详情页当前选中的版本，都只显示和修改该版本的点赞。Host 在每一轮锁定点赞后，系统按“点赞数 + 1”作为权重抽取开发来源并启动平台内 AI 开发。Creator 可以继续修改生成的草稿，确认后点击“发布并且保存”：版本发布到平台的同时，浏览器会把该 V0、V1 或 V2 的 HTML 代码下载到本机。每个 App 最多有两轮 Community Version，完整来源链和版本谱系会保留在研究数据中。

每个 App 使用独立的自动流程：V0 发布 → 第一轮评论与综合 → 第一轮系统开发 → V1 发布 → 第二轮评论与综合 → 第二轮系统开发 → V2 发布并完成。第一轮和第二轮不需要 Host 手动开放；只要所属测试或正式总流程已开始，V0 和 V1 发布后就会自动开放对应轮次的互动入口。

Host 可以选择一个或多个满足相同前置条件的 Creator，批量锁定第一轮或第二轮并启动系统开发。如果任一所选 App 不满足条件，整批操作会被拒绝，避免只推进部分 Creator。每个 Creator 行会显示当前轮次的普通评论总数和综合评论总数；切换到下一版本时，计数自动切换到新一轮。

所有 GPT-5.5 开发任务使用服务器端共享 Key 池。每个任务独占一把空闲 Key；没有空闲 Key 时按进入顺序排队，Creator 与 Host 都能看到“排队中”及当前位置，获得 Key 后自动开始。任务完成或失败后 Key 必定释放给下一项任务。

所有新生成作品都内置动画性能保护：连续动画最高以 30 FPS 运行，独立下载运行时设备像素比最高为 1.5，页面不可见时暂停。平台上的草稿和作品详情页使用 30 FPS、设备像素比最高 1 的展示层保护；社区首页的作品缩略预览限制为 5 FPS、设备像素比最高 1、暂停 CSS 动画，并仅在接近可视区域时加载，离开后卸载。下载接口仍返回作品保存的原始 HTML，不会把平台的 DPR 1 或首页 5 FPS 缩略模式写入下载文件。

Host 可以把所选 App 回退到上一个非破坏性流程；运行中的开发任务或已经生成的待发布草稿不能直接回退。Host 面板会显示每个 App 两轮开发的运行状态、完成时间和错误详情。失败任务或尚未发布的已完成草稿可以重新开发；已发布的 Community Version 不会被覆盖或回退。

Creator 发布 Initial App 后，已发布状态卡会显示“删除这个 App”按钮。只有该作品从未收到普通评论、回复或综合评论时，Creator 才能删除；一旦检测到任何评论，按钮会禁用并提示“作品已有评论，不能删除”。删除请求始终使用作品 ID 与当前 Creator 身份进行所有权校验，只清理该作品及其点赞、版本、草稿、任务等附属数据，并让该 Creator 回到可重新创建状态；其他 Creator 的作品、评论和流程保持不变。

## 清除测试角色数据

Host 控制台提供“清除测试角色数据”功能。输入确认短语 `清除测试角色数据` 后，系统永久删除测试角色的：

- 登录会话与行为事件；
- Initial App 和 Community Version（包括作品本身）；
- 草稿、开发对话、AI 任务及进度；
- 评论、回复、综合评论、点赞、收藏、通知和分配记录。

测试角色账号和 Host 保存的测试角色名单会保留，因此清除后可以重新登录并再次进行测试。正式角色的作品和互动不会被删除。若测试角色仍有运行中的 AI 任务，系统会阻止清除，直到任务结束。

## 数据导出与验证

Host 可导出当前研究 JSON，用于分析作品、版本、互动、综合来源、每个 App 的独立流程、开发任务和行为事件。

测试流程与正式流程互相独立：任一流程结束后，其流程卡片都会单独显示“新建研究”。Host 点击后，浏览器会先下载 ZIP 归档；ZIP 的根文件夹名称是点击时间（`YYYY-MM-DD_HH-mm-ss`），其中 `research-data.json` 保存该流程的研究数据，`apps` 文件夹保存各 Creator 的 V0、V1、V2 和未发布草稿。ZIP 完整获取后，系统才会清空并重置该流程，另一个流程的状态、作品和互动保持不变。若下载失败，系统不会执行重置。

自动验证脚本 `npm run test:community-gallery` 覆盖账号密码校验、测试/正式角色双向隔离、V0/V1/V2 自动轮转、按 App 锁定与回退、失败后重新开发、时间命名 ZIP 内容、正式/测试流程独立重置，以及清除测试数据后保留正式数据和测试账号可重新登录。
