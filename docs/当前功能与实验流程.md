# Vibe Gallery 当前功能与实验流程

更新日期：2026-07-26

## 平台定位

Vibe Gallery 是一个异步的 social vibe-coding 协作平台。它不把评论停留在“讨论”，而是让社区成员把多条评论组织为可追溯的综合方向，再由 App 的 Creator 在平台内将 Host 锁定的方向开发为可运行的 Community Version。

首页是瀑布流画廊。每位 Creator 自由发布自己的 Initial App；任意已发布 App 立刻可以被所有参与者浏览、评论和回复，不等待 6 个作品或 Host 开始研究。

## 参与者与条件

- `H01`：Host，负责开始/结束研究，并推进两个开发阶段。
- `C01–C12`：Creator，每人发布一个自由主题的 Initial App；每个条件各 6 人。
- `P01–P24`：Community Commenter；所有人都能看到并评论全部已发布 App，没有组别可见性限制。
- Control：普通社交评论与回复；Creator 在外部 vibe-coding 工具中开发后上传 HTML。
- Vibe Gallery：在普通社交互动基础上，增加收藏夹、两轮综合、来源连线和平台内 AI 原型开发。

## Vibe Gallery 的用户流程

### 1. Initial App 与异步讨论

Creator 发布 Initial App 后，任何参与者都可在详情页：

- 发表普通评论；
- 回复任意评论；回复以统一尺寸的小卡片挂在原评论下方，不再随嵌套深度继续缩小；
- 点赞、继续讨论；
- 将一条普通评论、回复或已有综合收藏到自己的收藏夹。

收藏夹是私有的跨 App 素材库。收藏本身不会让其他 App 的评论长期出现在当前画布：只有进入综合选材时，收藏内容才会临时显示；发布综合后，实际被采用的跨 App 内容才会作为正式来源节点保留。

### 2. 第一次综合：评论 → 可开发方向

研究开始后，画布开放“创建第一次综合”。参与者点击按钮进入选材模式：

1. 只能点击左侧的普通评论、回复或来自收藏夹的评论；单击选中，双击取消；
2. 每条综合选择 2–3 个来源，且至少一条来自当前 App；
3. 确认选材后输入一段可直接用于 vibe-coding 的完整提示词；
4. 发布为第一次综合候选。

来源卡片与综合候选之间自动连线。被采用的评论组会排在靠上位置；评论回复仍紧贴原评论，而不是混入独立的平铺列表。评论内容超过卡片默认展示长度时，可在卡片内展开或收起。

### 3. Host 锁定第一次开发

Host 在每个实验组 App 都至少有一个第一次综合候选后，点击“锁定方向并进入第一次开发”。系统对每个 App 独立选择一个候选：

```text
某条候选的社区分 = 它的每个直接来源
                  被多少位不同的候选作者选中过
                  的次数之和
```

同一用户即使多次使用同一来源，也只计一次。分数更高的候选优先；平分时按直接赞同票、来源数量、创建时间和 ID 决定。Host 的作用是统一锁定阶段，而不是逐条主观挑选。

在当前综合轮尚未锁定时，用户可以撤回自己的一条本轮综合候选，并将它换成一张赞同票。每位用户在同一 App、同一轮只能换票一次；换票后不能再创建本轮候选。赞同另一条本轮候选后，计分时视为该用户也选择了被赞同候选的全部直接来源，因此会改变来源选择人数与候选社区分。撤回记录仍保留在研究数据中，但不再显示或参与计分。

被锁定方向的直接与递归来源贡献者会立即收到站内消息；下次登录时可在消息栏看到，首次打开未庆祝消息会出现烟花效果。

Host 在本轮尚未开始生成、上传 Community 草稿或发布 Community Version 时，可以点击“返回上一阶段”。系统会撤销本轮锁定、恢复各 App 上一轮的入选方向，并移除本轮尚未生效的贡献通知；开发一旦开始，按钮即禁用，以免破坏版本与实验数据。

### 4. Community Version 1：平台内原型开发

只有目标 App 的 Creator 能开发该 App，且只能开发 Host 锁定的候选：

- V1 固定基于 Initial Version；
- 系统将综合提示词、完整来源链和基础版本交给平台内 AI；
- Host 锁定后，系统自动把入选综合评论的完整提示词带入开发，不要求 Creator 重新复制或重写；
- Creator 可试玩草稿、继续让 AI 修改，并确认发布 Community V1；
- 首页保留 Initial Version 原始卡片；App 发布社区版本后，在其右侧生成一张等高等宽的最新 Community Version 卡片。两张卡片相邻展示，明确它们属于同一个 App，同时社区卡片始终只呈现最新已发布版本及其真实来源。

对照组在同一开发阶段用外部工具完成 V1 后上传；平台不提供综合画布和平台内 AI 开发入口。

### 5. 第二次综合与 Community Version 2

某个 App 的 V1 发布后，画布增加第三、四列：

- 第三列显示针对 Community V1 产生的第二轮评论、回复，以及第二轮采用的跨 App 来源；
- 第四列显示第二次综合候选；
- 创建第二次综合时，可以选择第一列、第二列或第三列中的评论、回复、第一次综合及合规的收藏夹来源；
- 仍选择 2–3 个来源，且至少一条与当前 App 相关；
- 输入完整提示词后形成第二次综合候选。

当全部实验组 App 都已发布 V1，且每个 App 都有第二次综合候选时，Host 点击“锁定方向并进入第二次开发”。V2 只能使用 Host 锁定的第二次综合候选，并且**固定基于 Community V1**继续开发；不能回到 Initial 重新开始。每个 App 最多发布 V1 和 V2 两个 Community Version，所有旧评论、综合和版本均保留。

## 画布结构

```text
第一轮评论与采用来源 ──→ 第一次综合 ──→ Community V1
          │                   │
          └─────────┬─────────┘
                    ↓
          第二轮评论与采用来源 ──→ 第二次综合 ──→ Community V2
```

- 第一列：Initial Version 下产生的第一轮评论、回复与第一轮采用来源；
- 第二列：第一次综合候选；
- 第三列：Community V1 下产生的第二轮评论、回复与第二轮采用来源；
- 第四列：第二次综合候选；
- 连线只表示直接来源；点击“来源”可查看作者、原 App、版本和正文；
- 卡片不能自由拖动，位置由系统稳定排列，方便阅读来源关系而不变成无限画板。

## 数据记录与研究可分析性

系统记录 App 与版本、普通评论树、收藏夹、每轮综合、撤回换票、直接来源、Host 锁定结果及其社区分、开发任务、AI 交互、发布、贡献通知和关键行为事件。

这支持分析：

- 评论如何成为综合方向，再进入 V1/V2；
- 每个 Community Version 吸收了多少不同贡献者、评论、回复和跨 App 来源；
- 哪些来源被多个参与者反复选择；
- Control 与 Vibe Gallery 在评论到可运行原型的路径、操作负担和来源可追溯性上的差异。

自动验证脚本：`npm run test:community-gallery`。它覆盖即时评论、回复关系、跨 App 收藏、按不同用户的来源选择计分、Host 两次锁定与安全回退、V1/V2 门控、固定 V2 版本谱系和通知。
