# Vibe Gallery 当前功能与实验流程

更新日期：2026-08-07

## 参与者与登录

- Host：账号 `0`，密码 `0`。
- Creator：账号为实验编号 `1–30`，密码与实验编号相同。
- 数据库内部仍使用 `H01`、`C01–C30` 作为稳定研究编号；登录界面只要求输入数字账号和密码。

## 单次实验与测试角色

平台只运行一种实验流程，不再提供对照组或对照功能。Host 在研究开始前选择若干 Creator 作为测试角色并保存。保存后：

- 测试角色只能看到测试角色创建的作品和相关互动；
- 正式角色只能看到正式角色创建的作品和相关互动；
- Host 可以查看和管理两类数据；
- 作品、版本、评论、综合评论、点赞、收藏、分配、通知和开发任务都遵守同一隔离边界；
- 研究开始后测试角色名单锁定，避免中途切换导致实验数据混杂。

## 创作与社区开发

Creator 发布 Initial App 后，在 Host 开始研究后可以体验同一角色空间内的其他作品，并进行普通评论、回复、点赞、收藏和综合评论。Host 在每一轮锁定点赞后，系统按“点赞数 + 1”作为权重抽取开发来源并启动平台内 AI 开发。Creator 可以继续修改生成的草稿，确认后发布 Community Version。每个 App 最多有两轮 Community Version，完整来源链和版本谱系会保留在研究数据中。

## 清除测试角色数据

Host 控制台提供“清除测试角色数据”功能。输入确认短语 `清除测试角色数据` 后，系统永久删除测试角色的：

- 登录会话与行为事件；
- Initial App 和 Community Version（包括作品本身）；
- 草稿、开发对话、AI 任务及进度；
- 评论、回复、综合评论、点赞、收藏、通知和分配记录。

测试角色账号和 Host 保存的测试角色名单会保留，因此清除后可以重新登录并再次进行测试。正式角色的作品和互动不会被删除。若测试角色仍有运行中的 AI 任务，系统会阻止清除，直到任务结束。

## 数据导出与验证

Host 可导出当前研究 JSON，用于分析作品、版本、互动、综合来源、开发任务和行为事件。自动验证脚本 `npm run test:community-gallery` 覆盖账号密码校验、测试/正式角色双向隔离、Host 可见性，以及清除测试数据后保留正式数据和测试账号可重新登录。
